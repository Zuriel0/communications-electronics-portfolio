Monitor concurrente de logs vía SSH.

Una dirección MAC. Varios destinos posibles. Una herramienta de línea de comandos que reúne las búsquedas de logs remotos en una sola vista operativa.

Desarrollé la herramienta de monitoreo para buscar en logs web y de autenticación desde Ubuntu. Este caso describe el diseño y el flujo de trabajo según el relato de mi proyecto.

Encontrar una petición sin conocer su destino.

Un balanceador decide qué servidor web atiende cada petición entrante. Al investigar una dirección MAC, el operador no sabe de antemano qué servidor contiene el evento relevante. Revisar cada máquina por separado dispersa la investigación entre varias fuentes de logs.

El desafío de ingeniería

Observar todos los posibles destinos web conservando la visibilidad de autenticación. Una coincidencia web debe identificar el origen sin terminar la supervisión RADIUS.

La secuencia del negocio y el orden del monitoreo son distintos.

El flujo de negocio documentado avanza de una operación web exitosa a la autenticación RADIUS. La observación abarca ambos dominios de forma concurrente mediante grupos independientes. Iniciar ambos observadores no convierte la transacción de negocio en paralela.

Orquestación local. Observación distribuida.

La herramienta se ejecuta en una terminal Ubuntu. Bash coordina el flujo documentado, SSH proporciona el acceso remoto y la configuración externa define destinos, parámetros de conexión y política web opcional. Las coincidencias regresan a una consola central con su identidad de origen.

Entrada: validar y normalizar la dirección MAC antes de preparar la búsqueda.
Cobertura: monitorear seis servidores web de forma concurrente y un RADIUS configurado entre dos destinos disponibles.
Independencia: mantener separados los grupos de observación web y RADIUS.
Salida: conservar el servidor de origen, el tipo de fuente y la línea coincidente en una consola.
El límite entre la herramienta y su entorno.

El lado local contiene al operador, la configuración, el orquestador y la consola. El lado remoto contiene las conexiones SSH y las fuentes de logs observadas. La infraestructura monitoreada es el contexto operativo del proyecto.

Preparar la búsqueda

Recibir, validar y normalizar la MAC. Cargar el inventario de servidores, el RADIUS activo, los parámetros de conexión y la política web.

Observar las fuentes remotas

Preparar los patrones de búsqueda e iniciar el monitoreo concurrente de logs por SSH en el grupo web y el RADIUS seleccionado.

Conservar el origen

Reunir las líneas coincidentes en la consola con la identidad del servidor y el tipo de fuente para conservar su origen.

Aplicar la política web opcional

Cuando se habilita esta política, continuar la búsqueda en el servidor web que encontró la coincidencia y detener las demás búsquedas web. El monitoreo RADIUS continúa de forma independiente.

Una política para las búsquedas

Acotar el grupo web afecta a las sesiones de monitoreo, no apaga servidores web. Tampoco modifica el servicio de autenticación ni implica conmutación automática de RADIUS.

La entrada y la configuración preceden a la observación. La concurrencia describe el monitoreo remoto, no todas las operaciones de la herramienta.

Decisiones que preservan la visibilidad.
Buscar en los posibles destinos
La observación web concurrente resuelve la incertidumbre del balanceo. El operador no necesita elegir el servidor correcto antes de iniciar la búsqueda.
Mantener independientes los dominios de observación
Una coincidencia permite acotar el monitoreo web sin perder la visibilidad de autenticación. La política opcional tiene un límite definido: las demás búsquedas web, sin afectar RADIUS.
Hacer configurable el destino activo
El diseño documentado selecciona un servidor RADIUS en cada ejecución. Dos destinos disponibles permiten una elección configurable; esto no implica conmutación automática.
Centralizar sin perder el origen
Una sola consola reúne las coincidencias conservando el servidor y el tipo de fuente. La consolidación permite rastrear cada evento hasta su origen.

Tecnología en contexto

Bash aporta la automatización; Ubuntu es el entorno de ejecución local; SSH conecta la herramienta con las fuentes remotas. RADIUS identifica el dominio de autenticación. React Flow se utiliza para los diagramas de este caso de estudio, no para el monitor de línea de comandos.

Una vista operativa que conserva el origen.

El resultado reportado es un flujo de búsqueda centralizada en lugar de revisiones manuales por servidor: las coincidencias de MAC, sus servidores de origen y el contexto web/RADIUS pueden revisarse juntos.

Es un resultado cualitativo del relato de mi proyecto, no una prueba cronometrada de diagnóstico ni una medición de confiabilidad.

Capacidades demostradas en el proyecto

Automatización en shell, observación remota por SSH, diagnóstico por MAC, diseño de políticas de monitoreo y comunicación de arquitectura técnica.

Lección de diseño

La secuencia del negocio, la observación concurrente y la supervisión independiente describen responsabilidades distintas. Hacer explícitos esos límites es fundamental para interpretar esta arquitectura.
